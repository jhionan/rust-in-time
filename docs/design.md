# Rust in Time: Windows port

Port the current Antitimely Go application at commit `0a47e0b` into a standalone Rust executable, `rit`. Preserve project-aware parallel accounting, companies/projects, conjunctive priority rules, review and retroactive assignment, watched programs, pause/resume, reports and Git summaries, Claude/Codex/opencode transcripts, and invoice PDFs with advances. No Go runtime or macOS daemon, launchd, AppleScript, Accessibility, or Unix sockets.

## Approach

A direct behavioral port with a Windows platform adapter preserves the existing data model and avoids redesigning a working CLI. A Go wrapper would fail the language requirement; a GUI rewrite adds scope without improving accounting. The implementation uses SQLite WAL for both CLI and worker: short transactions and busy timeouts let commands operate while tracking continues, without exposing a network RPC endpoint. Windows Task Scheduler starts the worker at user logon; foreground `daemon` remains available for diagnostics. A per-data-directory exclusive file lock prevents duplicate trackers.

Data defaults to `%LOCALAPPDATA%/rust-in-time` on Windows and an isolated Rust-specific application directory elsewhere. `--data-dir` supports portable use, tests and copies of existing SQLite data. Never open or modify the live Antitimely database automatically. Preserve the original schema, with any added state in separate tables. Five-second ticks keep existing totals meaningful. Projects deduplicate timestamps; companies deduplicate across projects. Advances never move billing anchors. Money is integer cents and invoice allocation is transactional.

Windows executable names replace macOS bundle IDs in focus rules and allowlists; the underlying `bundle_id` schema field remains for portability. Windows paths compare without case sensitivity, normalize slash direction and respect directory boundaries. Unix paths retain case sensitivity. Only a terminal wildcard in the final path segment is accepted. Herdr space fields remain supported as optional metadata; absent metadata never matches a space rule.

Process enumeration/CPU and current directories use sysinfo, foreground window title and user idle use Windows APIs. Unreadable process directories are skipped rather than inferred from executable locations. CPU hysteresis, focus arming and idle thresholds retain Go behavior. New projects and resume-all queue arming requests in runtime_state; the worker consumes generations and tracks armed/suppressed state until focus/transcript activity or twelve present-user agent polls disarm it. Paused present-user CPU resumes and arms; idle CPU cannot resume. Unlike the Go fallback, unknown idle state uses the stricter CPU threshold to prevent phantom billing; transcripts remain independent. Claude and Codex collectors tail complete JSONL records, handle truncation, ignore stale/future activity, and use actual command directories for Codex. Claude live/import signatures share an empty binary name. Historical import splits chronological activity on directory changes before interpolating gaps, preventing an A-B-A session from billing A during B. Opencode is read-only. Tracking continues through temporary per-process or source failures with diagnostics.

## Module contracts

- `domain`: `Signal { source, bundle_id, window_title, binary_name, cwd, space_id: String }`, `Rule { id, project_id, priority: i64, match_bundle_id, match_title_substr, match_binary_name, match_cwd_prefix, match_space_id: Option<String> }`, `matches_cwd(pattern, cwd) -> bool`, `validate_cwd_pattern(&str) -> anyhow::Result<()>`, `match_rules(&Signal, &[Rule]) -> Option<i64>`, `propose_cwd(cwd, project) -> String`. Types derive Debug, Clone, Default, Serialize, Deserialize.
- `store`: `Store { pub conn: rusqlite::Connection }`, `Store::open(&Path) -> Result<Store>`, `Store::memory() -> Result<Store>`, `rules(&self) -> Result<Vec<Rule>>`, `record_signals(&mut self, ts:i64, signals:&[Signal]) -> Result<usize>`, `add_rule(&mut self, &Rule, retroactive:bool) -> Result<(i64,usize)>`. Raw connection also supports CLI transactions. Rules retroactively fill only unassigned ticks, respecting all rule clauses and ignored observations. Paused projects drop focus/CPU signals; matched transcripts unpause them. A timestamp is five-second aligned.
- `config`: `Config::load(&Path) -> Result<Config>`, `Config::default()`, `validate(&self) -> Result<()>`, serde YAML serialization; public string duration fields `interval`, `idle_threshold`, `transcript_grace`; u64 CPU thresholds, u32 rise/fall ticks; bool transcript_tracking; PathBuf transcript_root, codex_root, opencode_db; optional PathBuf db_path. Empty or literal `off` transcript paths disable a source. Shared YAML can contain invoice settings.
- `tracker`: `run(data_dir:&Path, config:&Config, once:bool) -> Result<()>`. Worker writes `runtime_state` SQLite key/value metadata for CLI status (heartbeat, start, idle); uses config db_path or data_dir/db.sqlite. Graceful Ctrl-C and file locking.
- `invoice`: `execute(conn:&mut Connection, config_path:&Path, command:&str, args:&InvoiceArgs) -> Result<serde_json::Value>`, `InvoiceArgs { company:Option<String>, id:Option<i64>, from:Option<String>, to:Option<String>, issue_date:Option<String>, at:Option<String>, note:String, amount:Option<String>, discount:Option<String>, no_credit:bool, dry_run:bool, force:bool }` derives Default. Supports generate/advance/balance/send/list/delete. CLI displays returned JSON or a readable serialization. Invoice settings use the same senders/clients/invoice YAML shape as Go. No emails or external transmissions.
- `cli`: clap subcommands, commands query SQLite directly; `--json` for scripting, explicit deletion/reset confirmation, stable usage/runtime errors. Non-Windows hosts can run all data and transcript workflows; Windows foreground/process adapter is platform guarded.

## Validation

Meaningful unit tests cover Windows boundaries/globs, rule precedence and conjunctions, retroactive attribution, pause override, signal/timestamp dedup, company dedup and billing anchors/credit. Filesystem fixtures cover partial transcripts and path attribution. CLI integration uses temporary directories and isolated data. Format, clippy, test and release build run locally. Windows CI tests and builds the native executable and uploads an artifact. Cross compilation checks the Windows API code when available; local macOS cannot prove live Windows window/idle capture.
